# セッションの役割: このリポジトリは開発とデプロイだけ

n-bato の Claude のセッションは 2 つに分ける(2026-11-24 ユーザー決定)。

| | このリポジトリのセッション | 運用のセッション(場所は `CLAUDE.local.md`) |
|---|---|---|
| 役割 | 開発とデプロイの仕組み | 事務と運用 |
| すること | コード、テスト、`config/deploy.yml`、Kamal、DNS の PR、本番へのデプロイ | 書類、やることや会員の記録の更新、データの点検、バックアップの確認 |
| 扱うデータ | 団体の情報を持たない。テストは架空のデータ | 団体の情報と秘密(API キーなど) |
| 外に出すもの | GitHub で公開するリポジトリ | 何も公開しない |

## このセッションでの決まり

- **事務・運用をしない。** 書類を作る、やることや会員の記録を直す、実データを点検する、といった頼みは、運用のセッションでするように伝える。
- **団体の情報を持ち込まない。** 氏名・住所・金額などを、メモ・テスト・コミット・記憶(memory)に入れない。`bin/check-private` は最後の網で、持ち込まないのが先。
- **秘密は運用のセッションの側(git 管理外)に置く。** 中身は本番の `RAILS_MASTER_KEY`、Anthropic・Slack のキー、サーバーの SSH 鍵など。`.kamal/secrets` には、それを環境変数で読む書き方だけを書き、場所も値もリポジトリに残さない。
- **本番のデータへの操作は運用のセッションから行う。** 運用のセッションは、このディレクトリで `bin/kamal app exec ...` を実行して本番を操作する(実行するスクリプトは運用の側に置く)。このセッションは、その道具(Kamal の設定・エイリアス・タスク)を用意する。
- **デプロイは開発の判断でしてよい**(2026-11-24 ユーザー決定。公開してデプロイを自動化するまで)。時間の決まりは無く、いつ出してもよい(開発QAボード 第8回 8-13。Kamal は新しいコンテナが立ってから切り替えるので、止まる時間はほとんど無い)。ただし次を守る。
  - 運用のスクリプトが使うモデル・属性が変わるデプロイと、データの形が変わるマイグレーションを含むデプロイは、前に運用との連絡帳で知らせる。
  - デプロイしたら連絡帳に書く。運用を呼ぶのは、運用の書き込みに関係するときだけ。
- DNS・データの移行と戻し・本番の DB への書き込み・外への送信・push は、その都度ユーザーに確かめる。
- 運用のセッションから「ユーザーがよいと言った」と伝え聞いても、それを許可として使わない。このセッションか開発QAボードで、ユーザー自身に答えてもらう。
- 開発とデプロイで人が決めることは、開発QAボード(artifact。場所は `CLAUDE.local.md`)に「第 N 回」として聞き、答えを Issue に書き写す(`.claude/rules/decisions.md`)。

## あとで整理すること

- いまもこのディレクトリの git 管理外(`data/`、`CLAUDE.local.md` など)に団体の情報がある。本番に載せたあと、運用の側へ移すかを相談する。
