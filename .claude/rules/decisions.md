# 人が決めること: 開発QAボードで聞き、Issue に記録を積む

開発とデプロイで人(理事長)が決めることは、開発QAボード(artifact、場所は `CLAUDE.local.md`)に「第 N 回」として聞く(2026-11-24 ユーザー決定)。決めたことの記録(ADR に当たるもの)は **Issue に積み上がる**ようにする。Issue を読めば、次が分かること:

- 何を決めないといけないか
- 判断の軸(ドライバー: なぜ決めるか、何を比べるか)
- どの案を選んだか、AI のおすすめはどれだったか
- おすすめ以外を選んだときは、その理由

## 進め方

1. **聞く**: ボードの質問に、対応する Issue を付ける(項目の `issue`。無ければ先に Issue を作る)。1 問 = いま・判断の軸・問い・案(おすすめに印、案ごとの注)。
2. **Issue に「判断待ち」を書く**: 聞いたらすぐ、その Issue に同じ中身をコメントする(見出し「判断待ち: 開発QAボード 第 N 回」、1 問ごとに「決まったこと: (答え待ち)」)。
3. **答えを書き写す**: 答えが出たら、その Issue に「決まったこと: 開発QAボード 第 N 回」をコメントする。1 問ごとに、選んだ案・おすすめだったか・ひとこと(おすすめ以外ならその理由。書いてなければ聞き返す)・それを受けて AI がすること。ボードの返事(`replies/<id>`)にも同じ要点を書く。
4. **設計の大きな決定**は、これまでどおり `docs/adr/` にも書き、Issue から ADR へ、ADR から Issue へ互いにリンクする。

## 気をつけること

- Issue は公開。団体の情報(氏名・住所・金額・内部の予定の細かいところ)は書かない。書く前に `bin/check-private` に通す。
- 伝え聞いた「よいと言った」は答えにしない(`.claude/rules/session-roles.md`)。
- UI の変更の合意は、これまでどおり見直し票で取る(CLAUDE.md「画面の決まり」)。
