# イベントの決まりは、設計とテストで守る

## 状況と問題

イベントは「日時は 1 つ・追加だけ」にしたい(ADR-0002)。これを仕組み(readonly? の上書きやデータベースのトリガー)で強制するか、設計とテストで守るかを決める。

## 判断の基準

* 間違ったコードが入ったら気付けること
* マイグレーションや保守のタスクで、どうしても直す必要が出たときに邪魔にならないこと

## 検討した選択肢

* モデル(readonly?)+データベースのトリガー+テストの 3 重で守る
* 設計(ADR・台帳)とテストで守る

## 決定

採用:「設計とテストで守る」。理由: readonly? やトリガーは、マイグレーションのようにどうしようもなくなったときに邪魔になる(理事長の判断)。決まりは設計として ADR と台帳に書き、テストで書き方を確かめる。

* イベントのクラスは EventRecord を含め、event_of で日時の列と作る入口を宣言する。
* イベントの表には created_at・updated_at を付けない。日時は宣言した列 1 つだけ。
* アプリのコード(app/)から、イベントを update・destroy しない。作るのは作る入口だけ。
* マイグレーション・保守のタスク(db/・lib/tasks/)からは直してよい。直したら、理由を ADR か notes に残す。

### 結果

* 良い: 保守のときに困らない。
* 悪い: テストが見ていない書き方(例えば SQL で直接書き換える)は止められない。レビューと台帳で補う。

### 確かめ方

test/models/event_rules_test.rb: イベントのクラスごとに、日時の列が 1 つでそれが宣言した列であること、created_at・updated_at が無いこと、app/ のほかのファイルからそのクラスの create・update・destroy を呼んでいないこと。
