# リソースを変えるとき: 業務の変更はイベント、打ち間違いの訂正は操作履歴

## 状況と問題

人の住所・名前や科目の名前を、表の画面でその場で書き換えている(自動保存。操作履歴に残り、元に戻せる)。イミュータブルデータモデルでは、リソースを更新したくなったら、隠れたイベントを探す。

## 判断の基準

* 業務として意味のある変更(住所の変更・改姓・退会・役員の就任と退任)が、日付付きで残ること
* 表で入力する画面の使いやすさを壊さないこと

## 検討した選択肢

* 業務の変更はイベントにし、打ち間違いの訂正は操作履歴に残してその場で直す
* リソースの変更は、すべて名前の付いたイベントにする(打ち間違いの訂正も「訂正」イベント)

## 決定

採用:「業務の変更はイベント、打ち間違いの訂正は操作履歴」。理由: 打ち間違いのたびにイベントを作るのは、表の画面には重い。操作履歴(AuditChange)は直す前の値を持つ変更の記録なので、訂正の追跡はできる。

* どの変更がイベントになるかは、項目ごとに台帳に書く。

### 結果

* 良い: 改姓・転居のような出来事が、届出や登記のやることにつながる。
* 悪い: どちらに当たるかの判断が要る(台帳で決める)。

### 確かめ方

会員の業務を移すとき(移す順の 2 番目)に、台帳に変更の種類を書き、テストで確かめる。
