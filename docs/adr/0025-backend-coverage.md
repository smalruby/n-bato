# バックエンドの自動テストのカバレッジを 100% にする

## 状況と問題

ロジックをモデルに寄せる(ADR-0002・0008)のに合わせて、バックエンドのコードがすべて自動テストで通っていることを確かめたい。

## 検討した選択肢

* 全体の数値の目標(例えば 90%)を置く
* バックエンド(モデル・コントローラー・ジョブ・ヘルパーなど)を 100%。実機が要るところだけ明示して外す。ビューと JavaScript は対象外

## 決定

採用:「バックエンドを 100%」。

* 測り方: `COVERAGE=1 bin/rails test`(simplecov。結果は coverage/、git 管理外)。ビュー・JavaScript・アセット・設定・マイグレーション・rake のタスクは対象外。
* 実機が要るところ(パスキーの端末など)だけ `# :nocov:` で囲み、理由をコメントに書く。
* イミュータブルデータモデルに移した業務から順に 100% にする(移す順は ADR-0002)。

### 理由

* ロジックはモデルに書くので、画面(ビュー・JavaScript)は 0% でよい(理事長の判断)。
* 推測: 「何となく 90%」より、移したところは 100% と決めたほうが、抜けに気付ける。

### 確かめ方

移した業務のファイルが 100% であることを、移すたびに確かめて記録する(2026-11-23 の会計: 証憑・AI の提案・承認・却下・取り下げ・照合で 100%。全体は 89.8%)。
