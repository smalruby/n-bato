# 会員の作り替え(入会・会員資格・役員の任期)

出どころ: 見直し票 第20回(r20-history で「会員の作り替えをまとめて進める」を選んだ)。移す順(ADR-0002): 会計 → **会員** → やること・依頼 → 手続き・決議・提出・登記。

## 状況と問題

会員のまわりのモデルは、イベントに分ける前の形だった。入会申込は、認めた・認めないを状態の列(status)の書き換えで表していた。会員資格の会費の納入、役員の退任も、列の値として持っていた。

## 判断の基準

* 出来事として残すべきもの(誰がいつ認めたか)が残ること
* いまの画面と使い方を変えないこと(作り替えは画面を変えない)
* 画面のない出来事のために、使われない入口を作らないこと

## 検討した選択肢

* 入会・会費の納入・退任を、すべていまイベントに分ける
* 入会(認めた・認めない)と住所・氏名(ADR-0029)はいま分け、会費の納入と退任は、その画面を作るときに分ける(採用)

## 決定

採用:「入会と住所・氏名はいま。会費の納入と退任は、画面を作るとき」。

* 入会申込(MemberApplication)は長いイベント。認めた = `MemberApplication::Approval`(approve!。人の記録と正会員の資格を作る)、認めなかった = `MemberApplication::Rejection`(reject!。理由は必須)。申込の status・人・年度・入会日・決めた日・理由は「いまの状態」で、入口だけが書き換える(ADR-0005)。照合は model:verify。
* 認める・認めないは、元に戻せない操作にした(ADR-0007 に合わせた。これまでは「元に戻せます」だった)。間違えたときは、人の記録と会員資格を直す。
* 会員資格(Membership)の会費の納入、役員の任期(OfficerTerm)の退任(left_on)は、いまは記録する画面が無い(会費は 2027 年度から)。その画面を作るときに `Membership::FeePayment`・`OfficerTerm::Resignation` に分ける。台帳には「待」のまま理由を書いた。
* 役員の任期の始まり・終わり(starts_on・ends_on)は、選ばれた任期という中身の日付なので、列のまま持つ。代表権のある任期ができると、登記の事由(ADR-0031)を作る。

## 結果

* 良い: 誰がいつ入会を認めたかが、出来事として残る。
* 悪い: 入会を認めたあとの「元に戻す」はできなくなった。会費の納入と退任は、まだ列のまま。
