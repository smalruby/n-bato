# 年度ごとの持ち方・監査の役割・AI に聞く — 見直し票 第7回・第8回

## 状況と問題

AI の推奨で決めたこと(年度ごとの持ち方、締める場所、監査の役割、AI に聞く)を確かめ、役割の切り替え方を決める。

## 検討した選択肢

* 会員・役員・法人情報: ID は共通にし、年度ごとの属性を別テーブルに持つ / 年度ごとに丸ごと写す
* 監査の役割: 閲覧だけの利用者を作る / 同じ人が役割(事務・監査)を切り替える(上部バー / 右ペイン)
* AI に聞く: 操作は人が「実行」を押してから / AI がそのまま行う
* AI に聞く欄の文を外部の API に送ってよいか: 個人情報を含む頼みごとも送る / 送るが個人情報を含む頼みごとには使わない / まだ使わない
* 利用者の管理画面: 監事にログインしてもらうときに作る / いま作る
* 科目の選択肢: 使ったものを先に出し、「すべて」を選ぶと残りを読み込む

## 決定

* ID は共通、年度ごとの属性は別のテーブル。写さないほうがよいものは AI が提案してよい
* 役割(事務・監査)は上部バーで切り替え、監査のときは帯を出す。監査は閲覧だけ
* AI に聞くの操作は、人が「実行」を押してから行い、操作履歴に残す
* AI に聞くは外部の API に送ってよいが、個人情報を含む頼みごと(住所の変更など)には使わない。人の記録は人の画面で直す
* 利用者の管理画面は、監事にログインしてもらうときに作る
* 科目の選択肢は、使ったものだけを先に出し、「すべての科目を出す」で残りを別に読み込む(項目が増えても遅くならないように)

### 理由

* 理事が監査として確かめたり、監査の人が直したりもありうるので、役割を切り替えられるほうがよい(答えのひとこと)
* 全件を最初から読むと遅くなることを心配した(答えのひとこと)
* 推測: 外部への送信は、個人情報を必要最小限にする団体の決まりに合わせた
