# ブラウザの「戻る」を使わなくてよい画面(パンくず・PDF は別のタブ)

出どころ: 見直し票 第21回。印刷のときに PDF を開くとタブが PDF に切り替わり、ブラウザの「戻る」でしか Nばとに戻れなかった。会員の詳しい画面から一覧へ戻る道も、ブラウザの「戻る」か左のメニューしかなかった。

## 状況と問題

ブラウザの「戻る」は、フォームの送り直しの確かめが出ることがあり、スマホでも使いにくい。理事長は「基本的にはブラウザの戻るを使わなくてよい UI」にしたい。

## 判断の基準

* どの画面からも、画面の中のリンクと左のメニューだけで行き来できること
* スマホの幅でも、いまどこにいて、どこへ戻れるかが分かること
* 一覧で絞り込んでいたら、その状態のまま戻れること

## 検討した選択肢

* PDF: 別のタブで開く(↗ を付ける)(採用) / 保存する(ダウンロード)。印刷の前に中身を目で見たいことが多いので、見られる別のタブにした。
* 一覧へ戻る道: パンくず(題の上)(採用) / 「← 一覧へ」のボタン / 両方。ボタンは「直す」「取り消す」などと並んで押し間違えやすい。

## 決定

* 詳しい画面・作る画面・直す画面の題の上に、パンくず「一覧 › この画面」を出す(ヘルパー `crumbs`)。
* 一覧へのリンクは、その一覧で最後に開いた URL(絞り込み・並べ替えのクエリつき)にする。一覧の index を GET で開いたとき、クエリがあればセッションに覚える(`remember_list_url`)。仕訳の絞り込みは前からセッションに覚えている。
* Nばとが返す PDF と外のサイトへのリンクは、別のタブで開き、文字の後ろに「↗」を付ける(ヘルパー `new_tab_link_to`。`target="_blank" rel="noopener"`)。
* 帳票の画面(印刷用のレイアウト)は、上の帯に「← 戻る」と「PDF ↗」を出す。
* 保存や出来事の記録は、送ったあと別の画面に移る(PRG)。いまの形を保つ。

## 結果

* 良い: スマホでも上の階層へ戻れる。PDF を閉じれば Nばとのタブが残る。
* 気をつけること: 新しい詳しい画面を作るときは、パンくずを付ける(結合テストで確かめる)。
