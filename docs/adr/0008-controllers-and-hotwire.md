# コントローラーは 7 つの基本のアクションだけ、出来事は create

## 状況と問題

1 つのコントローラーに、承認・却下・書き出しなどの独自のアクションが並び、ロジックもコントローラーにあった。

## 判断の基準

* コントローラーが薄いこと(確かめ・呼び出し・表示の準備だけ)
* Rails と Hotwire の流儀どおりで、AI も人も迷わないこと

## 検討した選択肢

* 独自のアクションを足していく
* 7 つの基本のアクションだけにし、出来事はその出来事の「作る」で表す

## 決定

採用:「7 つの基本のアクションだけ、出来事は create」。

* 例: 承認は POST /journal_proposals/:id/approval → JournalProposals::ApprovalsController#create。却下は /rejection。
* コントローラーがするのは、①パラメーターを確かめる、②イベントの入口(リソースなら save)を呼ぶ、③画面に渡す変数を用意する、の 3 つ。
* 画面の部分的な更新は Turbo Stream で返す。自動保存・元に戻すの仕組み(Stimulus)は、そのまま使う。

### 結果

* 良い: ルートを見れば、どんな出来事があるかが分かる。
* 悪い: コントローラーのファイルが増える。

### 確かめ方

移した業務から順に、独自のアクション(member の post など)をルートから無くす。
