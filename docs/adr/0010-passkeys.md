# パスキーでのログイン(パスワードと併用、ドメインごと)

## 状況と問題

ログインがメールアドレスとパスワードだけだった。パスワードは使い回し・盗み見・なりすましのページで漏れる。

## 判断の基準

* なりすましのページでは働かない認証
* 本番のドメインを用意するまでは、パスワードでも入れること

## 検討した選択肢

* パスワードだけ
* パスキーとパスワードの併用(ドメインを用意したあとでパスキーだけにする)
* パスキーだけ

## 決定

採用:「パスキーとパスワードの併用」。

* ライブラリは webauthn(cedarcode/webauthn-ruby、MIT)。ブラウザ側は navigator.credentials を直接使い、JavaScript のライブラリは足さない。
* パスキーはドメインごと(手元・ステージング・本番でそれぞれ作る)。親のドメインで共有しない。
* パスキーを足す・消す前は、10 分を過ぎていたら本人を確かめ直す。足す・消すは元に戻せない操作として履歴に残す。
* パスキーだけにするときに、端末をなくしたときの入り直し方を改めて決める。

### 確かめ方

自動テスト(webauthn の FakeClient で登録とログインの往復)と、実機(Mac・スマホ)で人と一緒に確かめる。
