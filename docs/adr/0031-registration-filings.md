# 登記の申請を 1 件ずつ記録し、申請書の文と添付書類を作る

出どころ: 見直し票 第20回(r20-flow・r20-text・r20-attach・r20-link)。登記はオンラインで進めたい(理事長)。

## 状況と問題

「登記」の画面は、原因の日・期限・登記した日を入れるだけだった。何をまとめて申請したか、申請番号・受付番号・補正のやりとりは残せなかった。申請書の「登記すべき事項」は、人が法務局の記載例を見ながら書いていた。重任の登記は、法務省の申請用総合ソフト(Windows 11 だけ)でしか出せない。添付書類は、署名付き PDF か、紙で郵送する。

## 判断の基準

* 申請の手順(申請した → 受付 → 補正 → 完了)が、出来事として残ること
* 重任・住所の変更・氏名の変更を 1 件の申請にまとめられること(まとめられないと言われたら分けられること)
* 申請書の文を Nばとの記録から作り、書き方は法務局の記載例に合わせること。推測で埋めないこと
* 添付書類を、手元の届出印で出せること

## 検討した選択肢

* いまの「登記」の行に、申請番号などの列を足す
* 登記の事由(Registration)と、登記の申請(RegistrationFiling、長いイベント)を分け、申請の手順をイベントにする(採用)
* 添付書類: 紙で郵送(採用) / 署名付き PDF(作った人全員の電子署名が要る。いまは向かない)

## 決定

* 登記の事由 `Registration`(長いイベント: 事由から登記まで): 理事の重任・就任(役員の任期から)、住所の変更・氏名の変更(ADR-0029 の出来事から)、その他。期限は原因の日から 2 週間(組合等登記令 3 条)。日が不明なら期限も不明。どの申請に入れたかと、登記した日(いまの状態)を持つ。重任か就任かは、同じ人の代表権のある任期がすき間なく続いているかで決める。
* 登記の申請 `RegistrationFiling`(長いイベント): `start!` で登記の事由をまとめて始め、書類を作っている間は足す・外す。詳細のイベントは `Submission`(申請した。申請番号)・`Acceptance`(受付。受付番号)・`Correction`(補正を求められた。何度でも)・`Completion`(完了。入れた事由を登記したにし、登記の完了を待っているやることを作業中に戻す)・`Withdrawal`(取り下げ。事由は入れ直せる)。日付は人が入れる出来事の日。どれも元に戻せない操作。いまの状態は、取下げ → 完了 → 補正 → 受付 → 申請 の順にイベントがあるかで決まる(model:verify で照合)。
* やることの「待ちが解ける決まり」(resume_rule = registration_completed)を足した。完了で、TechSoup へ送るなどのやることが作業中に戻る。
* 申請書の文 `RegistrationFiling::Statement`: 登記の事由・登記すべき事項・添付書類。定款で理事長・副理事長だけが代表する法人は、その人だけを資格「理事」で登記する。人ごとに「役員に関する事項」をまとめ、原因年月日を日付の順に並べる(重任・就任・住所移転・「旧氏名の氏変更」)。住所・氏名は、入れた事由のいちばん新しい日の値。旧氏を併記すると決めた人は「新しい氏名（旧氏 名）」。日が不明・氏と名を区切れない・住所が空・事由が 2 種類以上(1 件にまとめられるか)は「確かめること」に出す。
  * 出典: 法務局の記載例 001386707.pdf(NPO 法人の重任)・001252906.pdf(住所移転)・001252648.pdf / 001252649.pdf(氏変更・旧氏の併記)。https://houmukyoku.moj.go.jp/homu/content/
  * 法務局の相談で別の書き方を言われたら、Statement を直してテストで固める。
* 添付書類は紙で郵送する: 「書面により提出する添付書面の内訳」(申請番号を書く欄)・理事の互選書(届出印の欄。理事会の決議を選べばその議事録)・定款・社員総会議事録(決議を選ぶ)を HTML/PDF で作る。就任承諾書は議事録の記載を援用する。
* 登記・供託オンライン申請システムへのボタンと、使える時間(平日 8:30〜23:00、休日 8:30〜18:00、12/29〜1/3 は使えない)・いま使えるか・法務局の受付(平日 8:30〜17:15。過ぎたら次の平日)を、登記の画面の上に出す。どの法人でも同じなので、提出先ではなく `config/registration_online.yml` に持つ。祝日の暦は持たないので「祝日なら」と添える。

## 結果

* 良い: 申請の手順と番号が残る。申請書の文を写すだけになる。期限の数え方(受付の日)が分かる。
* 悪い: 書き方は記載例からの推測を含む(相談で確かめる)。祝日は判定しない。
