# 画面の変更は、見直し票で合意 → デザインシステム → 実装

## 状況と問題

画面ごとに見た目や操作がばらばらになるのを防ぎたい。人(理事長)が使い方を決め、AI が作る。

## 決定

採用:「見直し票で合意 → デザインシステム(docs/design-system/)に書く → 実装」。実装してから相談しない。デザインシステムに書いていない画面は作らない。小さな不具合の修正(崩れ・誤字)はこの限りでない。設計の大事な決定は、合意のあとで ADR にも書く(ADR-0001)。

### 確かめ方

見直し票の回ごとに、デザインシステムの版を上げ、実装のコミットに回の番号を書く。
