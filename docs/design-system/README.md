# n-bato 事務 UI

**N(エヌ)ばと**(n-bato)の画面の決まりごと。NPO 法人の事務員が毎日使う画面のための決まりごと。見た目は Excel 程度でよく、**1 画面にできるだけ多くの情報を載せ、入力したらすぐ保存し、すべての操作を履歴に残し、必要な画面では元に戻せる**ことを優先する。飾りは足さない。

## 原則

1. **詰める。** 1 行の高さは `row-height`(24px)、文字は `body`(13px)。余白は `space-5`(12px)より大きくしない。スクロールせずに 1 年度分の仕訳の大半、提出書類の一覧、期限の一覧が見えることを目指す。
2. **保存ボタンを置かない。** セルや入力欄は、確定(Enter・Tab・別のセルへ移る・入力欄から離れる)した時点で保存する。画面の上部バーの状態表示が「保存中…」→「保存しました 10:42」と変わる。
3. **すべて履歴に残す。** 誰が・いつ・どの記録の・どの項目を・何から何に変えたかを残す。消した行も履歴から復元できる。
4. **元に戻せる画面では、元に戻す・やり直すを必ず出す。** 上部バーの右に置き、⌘Z / Ctrl+Z と ⌘⇧Z / Ctrl+Y で操作できる。
5. **元に戻せない操作は、その場で確かめる。** 承認(記帳)、提出日の記録、決議の成立の反映、登記の記録は、ボタンの横に「取り消せません」と書き、2 回目のクリックで実行する(ダイアログは出さない)。
6. **年に一度の手続きは、手順の画面で進める。** 事業報告書等の提出・通常総会・役員改選・登記などは、1 年たつとやり方を忘れる。手順をすべて並べ、なぜやるのか(根拠の条文)と前回どうしたかを、手順ごとに見せる(下の「年に一度の手続き」)。
7. **画面と帳票を分ける。** 画面はゴシック(`ui`)と等幅の数字(`num`)、所轄庁に出す書類は明朝(`print`)と全角数字。帳票の決まりは所轄庁の作成例に従い、このシステムの色は使わない(黒一色)。

## 名前

- 日本語では **N(エヌ)ばと**。画面では N に「エヌ」のルビを振る(Brand)。ルビが使えない文では「N(エヌ)ばと」と括弧で書き、2 回目からは「Nばと」。
- 英字では **n-bato**(ハイフンを付ける)。

## 画面の骨組み(1 画面)

```
┌ 上部バー(bar-height 36px)─ Nばと │ 画面名 │ 年度 │ ……… 保存しました 10:42 │ ↶ 元に戻す ↷ やり直す │ 履歴 ┐
├ メニュー(nav-width 168px)┬ シート(残りの幅いっぱい)────────────────┬ 右ペイン(side-width 300px)┤
│ ホーム                    │ 列見出し(header-height 26px、固定)          │ 選んだ行の詳細          │
│ 証憑・AI 仕訳             │ 行 × 24px ……                               │ ─────────────           │
│ 仕訳 ◀                    │                                             │ 操作履歴(新しい順)     │
│ …                         │ 合計行(固定)                                │                         │
├───────────────────────────┴─ 年度タブ(Excel のシート見出しのように下に並べる)───────────────────┤
```

- 右ペインは畳める。畳むとシートが広がる。
- 画面の全体がスクロールするのではなく、シートの中だけがスクロールする(列見出しと合計行は固定)。

## 年に一度の手続き(手順の画面)

ふだんの画面(シート)は「毎日、たくさん、速く」入力するためのもの。年に一度の手続きは逆で、**たまにしかせず、やり方を覚えていない**。そこで、シートと同じ骨組み(上部バー・左メニュー・右ペイン)のまま、シートの場所に **手順の画面**(Procedure)を置く。

```
┌ 見出し(Deadline)─ 事業報告書等の提出 │ 令和7年度分 │ 期限 2026/06/30 143 日超過 │ ▮▮▮▯▯ 3/9 済み │ 次にやること 5. 総会… ┐
├ 手順の一覧(Stepper、232px)┬ 手順の中身(StepPanel)───────────────────────────┤ 右ペイン: 前回・操作履歴
│ ✓ 1. 決算を締める          │ 4. 理事会で議案を決める [待ち]                          │
│ ✓ 2. 事業報告書を書く      │ ┃ なにを・なぜ(guide 14px)                             │
│ ✓ 3. 監事の監査            │ ┃ 根拠 定款 第37条第3項                                 │
│ … 4. 理事会で議案… ◀       │ 同意の返事(Checklist) ☑ 理事長 ☑ … ☐ 理事 B 待ち      │
│ 5. 総会で承認              │ この手順で作る書類 [提案書] [同意書] [議事録]           │
│ ! 6. 松江市に出す          │ [この手順を済みにする] 返事がそろうと押せます           │
│ 当てはまれば  － 収益事業… │                                                          │
```

- **ウィザード(次へ・戻るだけの画面)にしない。** すべての手順を一覧にし、どれでも開ける。実際の手続きは順番どおりに進まない(同意書を待つ間に印刷の準備をする など)。
- **止めても続きから。** 何週間かかっても、開けば止まったところが出る。チェックと記録はすぐ保存し、元に戻せる。
- **説明は少し大きく。** ここだけは `guide`(14px・行間 24px)を使い、`guide-measure`(640px)より広げない。詰めるのは一覧と表で、説明の文は詰めない。
- **根拠と前回を必ず添える。** 根拠の条文は `guide` の中に、前回の日付とメモは右ペインに。
- **状態は 6 つ**: 未着手・進行中・待ち・済み・期限切れ・対象外。印の形・記号・文字で示す(Stepper)。
- **済みにするのは元に戻せる。外に出したことは取り消せない。** 提出日・申請日の記録は危険のボタン(2 回押し)。
- 手続きの種類(手順の並びと説明・根拠)はアプリの中に定義として持ち、年度ごとの進み具合と記録は別に持つ。定款が変わったら定義を直す。

## 色の使い方

- 地は `surface`(画面)と `sheet`(シート・入力欄)。偶数行と見出し行は `sheet-alt`。罫線は `grid-line`、見出しの下と合計の上は `grid-line-strong`。
- 文字は `ink`、補足・列見出し・読み取り専用は `ink-muted`。リンクと主ボタンは `accent`(塗りの上の文字は `on-accent`)。
- 選択中のセルは `select` の 2px の枠、選択範囲は `select-fill`。キーボードのフォーカスも同じ枠で示す。
- 保存の状態は色だけでなく形でも示す(セル右上の印と、上部バーの文字)。
  - 入力中(未保存): `dirty-fill` の地、印は `dirty` の三角。
  - 保存中: 印は `saving` の点。
  - 保存しました: `saved-fill` で 1 秒だけ染め、上部バーに `saved` で「保存しました」。
  - 保存できなかった: `error-fill` の地と `error` の枠、上部バーに理由と「再試行」。値は消さない。
- 変更できないセル(会計王から取り込んだ仕訳、承認済みの記録)は `readonly-fill` の地と `ink-muted` の文字。クリックしても入力欄にならず、上部バーに理由を出す。
- マイナスの金額は `error` の色で、先頭に「−」(全角マイナス)を付ける。色だけで符号を示さない。
- 履歴で「元に戻した」操作は `history-mark` の印で示す。
- 手順の状態は `step-*`(未着手 `step-todo`、進行中 `step-current`、待ち `step-waiting`、済み `step-done`、期限切れ `step-overdue`、対象外 `step-skipped`)。手順の説明の地は `guide-fill`、左の線は `guide-line`。`guide-fill` は説明(手順の説明と、右ペインの「この画面の使い方」)だけに使う。

## 文字

- `ui`(BIZ UDPGothic)を画面の全体に使う。金額・コード・日付は `num`(BIZ UDGothic)で桁をそろえ、右寄せ。
- 大きさは 5 段だけ: `title` 15px、`section` 13px 太字、`body` 13px、`label` 12px、`tiny` 11px。これより小さくしない。
- 例外は 2 つ: 手順の説明の `guide`(14px・行間 24px)と、製品名のルビの `brand-ruby`(10px)。期限の日数は `countdown`(15px 太字・等幅)。
- 帳票は `print`(BIZ UDPMincho)。`print-title` 14pt、`print-body` 10.5pt。

## 言葉

- 事務員の言葉で書く。「レコード」「エンティティ」ではなく「仕訳」「証憑」「会員」。
- ボタンは動詞で終える:「承認して記帳」「取り込む」「書き出す」。結果の表示は過去形:「記帳しました」「保存しました」。
- エラーは、何が起きたかと、どうすればよいかを書く:「保存できませんでした(通信が切れました)。再試行を押してください」。謝らない。
- 日付は画面では `2026/11/20`、帳票では和暦の全角(`令和８年１１月２０日`)。

## 保存と履歴の決まり(実装の目安)

- 保存は 1 セルずつ送る(PATCH、1 項目)。送ったら上部バーを「保存中…」にし、成功で「保存しました 時:分」、失敗で `error` 表示。続けて入力しても待たせない(送る順は守る)。
- 履歴は変更ごとに 1 件:操作した人、日時、記録の種類と ID、項目、変更前、変更後、操作の種類(作成・変更・削除・元に戻す・やり直す)。複数の項目をまとめて変える操作(行の追加、提案の承認)は 1 つの操作番号でまとめる。
- 元に戻すは、履歴の最新の操作の逆を「新しい操作」として記録する(履歴は消さない)。やり直すも同じ。元に戻せるのは、その画面で自分がした操作だけ。
- 元に戻せない操作(原則 5)は履歴に残すが、元に戻すの対象にしない。

## 年度(2026-11-20 見直し第2・3回で合意)

- **操作する年度は 1 つ。** 上部バーの年度の札(`nb-year-chip`)に出し、「他の年度に切り替える ▾」(`nb-year-switch`)でいつでも切り替える(2 回押しはいらない)。切り替えは人ごとに覚える。
- **直せるのは、操作している年度の記録だけ。** ほかの年度を直すときは、その年度に切り替えてから直す。年度をまたいで並べる画面(推移など)は見るだけ。
- **年度で区切るもの**: 会計(仕訳・証憑・科目と部門・期首の残高・決算・事業報告)も、会計以外(会員・役員・決議・登記・法人情報など)も、すべて年度で区切る。所轄庁(松江市)に年度ごとに報告する義務があるため(見直し第5回で合意)。
- **年度の色(YearTheme)**: 5 色(藍・青緑・紫・松葉・牡丹、トークン `year-1〜5-*`)を (年 − 2015) mod 5 + 1 で年度に当て、5 年で巡回する。上部バー・左メニュー・画面の地を年度の色にし、ボタン・保存・エラーなど意味のある色は変えない。4〜6 月に前の年度と今年度を行き来しても、画面全体の色で一目で分かるようにするため。`<body data-year-hue="n">` で付ける。
- **締める**: 年度を締める操作がある。締めたときのデータが、その年度の正になる(会計も会計以外も同じ)。会計は、決算をして締め、次の年度に切り替える。締めた年度の仕訳と科目は固定する。
- **締めた年度を変える**: 仕訳でも、過去の年度の役員の住所でも、変える前に理由を書いてもらう(理由なしでは保存しない)。変更はすべて記録に残す。
- **締める前の次の年度**: 前の年度を締める前から、次の年度の仕訳を入れられる。前の年度を締める前だと分かるようにし、次の年度の入力は「仮」として扱う。
- **年度ごとのデータセット**: 会員・役員・法人情報・科目と部門なども「いま」を 1 つ持たず、年度ごとのデータセットに属する(全項目)。変更は、どの年度のデータかを決めて行う。4 月の入会や 6 月に選ばれた役員は、前の年度を締める前でも次の年度のデータセットに入れる。
- **次の年度を始める**: 前の年度のデータセットを写して、次の年度のデータセットを作る(会計王の次年度更新と同じ。3 月でもよい)。
- **締める時期**: 所轄庁への提出を記録したときに「この年度を締めますか」と聞き、2 回押しで締める。それまでは前の年度を理由なしで直せる。
- **仮**: 前の年度を締める前の次の年度は「仮」。仕訳はふつうに入力・保存して帳簿にも入れ、行・残高・決算に「仮」の札を出す。前の年度を締めると札が外れ、期首の残高を計算し直す。仮の年度の仕訳を会計王へ書き出せるのは、前の年度を締めたあと。画面の上に「2025年度をまだ締めていません。2026年度は仮です」の帯(`nb-year-band`)を出す。
- **締める場所**: 手続き「事業報告書等の提出」の最後の手順「この年度を締める」(提出の記録のあと)。締めると次の年度の期首の残高を作り直す。締めを解くときは理由を書く。
- **変更の記録**: 年度ごとの変更(日時・人・記録・前の値・後の値・理由)を一覧する画面。締めたあとの変更だけに絞れ、監事に渡す印刷用(PDF)でも出せる。
- **ほかの年度にも同じ値があるとき**: ある年度で値を直したとき、ほかの年度(締めていない次の年度・締めた年度)に同じ値があれば「2025年度も直しますか」と聞く(締めた年度なら理由を書く)。引っ越しのように過去は正しかった場合は直さない。科目の追加・名前の変更も同じ。
- **再提出**: 提出したあとで締めた年度を直し、提出した書類の中身が変わるときは、その年度の手続き「事業報告書等の提出」に「再提出」の手順を自動で足し、ホームに出す。
- **最初の状態(2026-11-20)**: 2023年度以前は締めた年度(データセットは作らず、提出した PDF を年度に付ける)。2024年度・2025年度は締める前で、データセットは 11/24 の最終版の名簿から作る(様式にない項目は空)。2025年度は 2024年度を締めるまで、2026年度は 2025年度を締めるまで仮。年度は古い順に締める。2026年度には、いまの会員・役員の情報をこの年度のデータセットにする。
- **年度の外の日付**: 仕訳の日付が表の年度の外なら、保存せずに警告し、「○○年度へ移す」を押すと、打った内容を持ってその年度へ行ごと移す(元の年度からは消える)。移す先か元が締めた年度なら、両方の年度の状態(締めた・提出済み)と再提出が要ることを出し、理由を書いてもう一度押して移す。移したあとはその年度に切り替わり、移した行が光る。
- **変更の記録**: 変更はすべて、誰が・いつ・記録・項目・前の値・後の値・理由を残す(Audited)。年度ごとの「変更の記録」画面で一覧し、「締めたあとの変更だけ」で絞り込め、監事に渡す PDF を出せる(電子帳簿保存法の訂正・削除の履歴、不正の発見のため)。

## 役割(2026-11-21 見直し第8回で合意)

- 利用者ごとに、切り替えられる役割(事務・監査)を決めておく。理事長は両方、監事は監査だけ(当面は rake で決める)。
- **いま使う役割は上部バーで切り替える**(`nb-role-switch`)。年度と同じく画面全体にかかるので上部バーに置く。ボタンは「事務として使う ▾」の形で、事務は `pencil`、監査は `eye` のアイコン。切り替えられる役割が 1 つなら札(`nb-role-chip`)だけ。切り替えは人ごとに覚える(別の端末でも同じ)。
- **監査で使っているときは帯を出す**(`nb-role-band`)。「監査として見ています。記録は変えられません。」と、事務に戻せる人には「事務に切り替える」。帯は `dirty` の斜めの縞で、年度の帯より上に置く。
- 監査の役割は閲覧だけ(記録を変える操作は断る)。右ペインの説明は「この画面に出ているもの」「ほかに出せるもの」。

## やること(2026-11-21 見直し第9回で合意)

人がやることを 1 つの一覧(左メニュー「やること」)にまとめる。利用団体がそれまで使っていた「やること」の一覧と同じ形にする。

- **一覧(TodoList)**: 出どころごとにまとめる。出どころは 4 種類(入会申込は第11回で追加)。
  - **依頼**: 外から届いた依頼(松江市のメールなど)から作ったやること。依頼ごとにまとめる。
  - **義務**: 定款・法律の義務の期限(事業報告書等の提出、総会、役員の改選、登記、公告)。n-bato が自動で出す。
  - **手続き**: 進めている年に一度の手続きの、次の手順。
  - **入会申込**: 届いて、まだ認めていない入会申込(下の「入会申込」)。
  - 列は「状態・年度・やること・種類・担当・期限・開く」。年度は年度の色の札(`nb-ychip`)。年度で絞り込めるが、操作している年度では絞らない(年度をまたぐ一覧)。
  - ホームには、期限を過ぎたものと 30 日以内のものだけを出し、「やること」へのリンクを置く。
- **件数のまとめ(TodoSummary)**(2026-11-23 見直し第12回で合意): やることの画面とホームの上に、済んでいないやることの件数を札で並べる。開いてすぐ「急ぐものが何件あるか」「人がやるものが何件あるか」が分かるようにするため。
  - 札は「期限を過ぎた」(`error` の色)・「7 日以内」(`dirty` の色)・「それより先」・「期限なし」と、区切りの線のあとに「人がやる」・「AI がやる」。担当が AI だけのものが「AI がやる」、それ以外(理事長・AI の共同も)は「人がやる」。
  - 0 件の札は灰色にする(色を付けない)。
  - 札を押すと、その分だけに絞る(もう一度押すと戻す)。出どころ・年度の絞り込みと組み合わせられ、数もその絞り込みの中で数える。
- **年度**: やることは年度ごとのデータセットの外に置く。1 件の対象は 1 つの年度か「年度なし」。年度ごとに解決するものは年度ごとに分ける(H29〜R2 の名簿なら 4 件)。次の年度を始めても写さない。
  - 「開く」は、その年度に切り替えてから解決する画面へ移る。
  - 開いたやることの対象が締めた年度なら、理由の欄に「依頼名: やること」を最初から入れておく。
  - 年度を締める手順には、その年度が対象の済んでいないやることを出して確かめる。
- **状態**: 未着手・作業中・待ち・済みの 4 つ(`nb-st`)。待ちには、誰の何を待っているかを書く。
  - n-bato の記録で確かめられるもの(提出日を記録した、年度を締めた)は自動で済みにし、何をもって済みにしたかを残す。それ以外は、対話で「終わった」と書くか、行の「済みにする」+ひとことで済みにする。済みは元に戻せる(操作履歴)。
- **種類**: 画面(n-bato の画面で解決)・書類・人に聞く・電話や窓口。画面でないものは、手順と、使う書類やメモの置き場所を書き、人が済みにする。
- **作り方は AI との対話(RequestThread)**: 人が 1 件ずつ書く画面は作らない。
  - 依頼ごとに対話を持つ。「AI と依頼を整理する」で始め、メールの本文を貼り、添付(PDF・画像)を置く。
  - **送る前に伏せる**: 住所・電話・メールアドレス・郵便番号と、n-bato に登録されている人の住所などを `nb-mask`(黒地の「伏せた住所」など)に置き換え、人が確かめてから「AI に送る」。添付は伏せられないので、送るかどうかを人が選ぶ(既定は送らない)。
  - AI の案(やることを作る・直す・済みにする)は、人が「決める」を押してから記録する。
  - 依頼のやることが全部済んだら、依頼を「解決」にし、AI が送付状(または返信)の下書きを作る。送るのは人。
- 右ペインの「AI に聞く」に依頼らしい文が書かれたら、この対話へ案内する。
- Slack のメッセージからも、依頼の対話の下書きを作れる(下の「Slack への知らせ」)。

## Slack への知らせ(2026-11-21 見直し第10回で合意)

法人の Slack は、人に知らせる窓口にする。記録の正は n-bato のまま。

- **送る先**: 役員だけが入る非公開チャンネル 1 つ(ワークスペースには外の人もいる前提)。
- **知らせること**(最初はこの 3 つ):
  - 期限のリマインド: 週 1 回(月曜)の「今週のやること」(期限を過ぎたものと 2 週間以内)と、3 日前・当日。
  - 締めた年度の変更: 年度・操作・変えた項目(前 → 後)・理由・変えた人と時刻、「変更の記録を開く」。
  - 監事の監査が済んだ・年度を締めた/締めを解いた/始めた・所轄庁への提出を記録した。
- **文面**: 1 行目を太字の見出し(「*今週のやること*」など)にし、そのあと 1 件 1 行。最後に「Nばとで開く」のリンク(n-bato が手元で動いている間は理事長の PC でしか開けない)。
- **流さないもの**: 住所・電話・メール・生年月日・名簿・フォームの回答の中身・会員の名前。会員・役員・同意などの記録が変わったときは「(個人情報のため、値は出しません)」とだけ書く。役員の名前と「誰が変えたか」は出してよい。
- **しないこと**: Slack から記録を直接変えない(承認・同意・締める・仕訳の確定・監査の結論は n-bato で人が押す)。書面決議の同意を Slack で受けない。AI が Slack の会話を勝手に読まない。外への送信(松江市など)に使わない。
- **止まっていた間**: n-bato が止まっていた間の期限と記録は、次に動いたときにまとめて送る(同じ知らせは二度送らない)。
- **Slack からやることを作る**(2026-11-22 見直し第11回で合意): メッセージのメニュー(ショートカット)「Nばとのやることにする」を選ぶと、そのメッセージの文(と PDF・画像の添付)を、n-bato の新しい依頼の対話の**下書き**にする。AI へはまだ送らない(伏せた文の確認と送るのは n-bato で人が行う)。依頼の名前は「Slack から: 〈文の始め 20 字〉」、相手は選んだ人の Slack の表示名。Slack にはスレッドで「Nばとの『やること』に下書きとして入れました」とだけ返す(メッセージの中身はくり返さない)。受け取りは Socket Mode(n-bato から Slack へつなぎに行く。外から入る口は開けない)。n-bato が止まっている間に選んだものは届かないので、そのときは「いまは受け取れません」と Slack が出す。
- Slack アプリの登録・ワークスペースへの追加・チャンネルへの招待・トークンの発行は、公開・共有の設定にあたるので人が行う。
- **組み込む前に人と一緒に確かめる**(2026-11-22): 送る文面を先に見せ、1 件ずつ実際に送って、人が Slack で見て「よい」と言ってから、自動の知らせ(1 時間ごとの確認)と受け取りを動かす。それまでは Docker に鍵を渡さない。

## 入会申込(2026-11-22 見直し第11回で合意)

正会員の入会は、Google フォームで受け、AI が n-bato に「入会申込」として入れる(案 A)。申込はまだ会員ではない。理事長が認めたときに会員になる(定款第7条)。

- **左メニュー「会員・役員」の中に「入会申込」**: 一覧は新しい順。状態は「届いた」「認めた」「認めない」の 3 つ(StatusTag)。届いたものは「やること」にも「入会申込が届いた: 〈氏名〉」として出る(出どころ「依頼」の代わりに「入会申込」)。
- **申込の画面**: 申込の中身(氏名・ふりがな・年齢の区分・郵便番号・住所・メール・電話・総会の受け取り方・きっかけ・協力できること・ご意見・申込日)を Field で並べる。住所などは人の画面と同じく暗号化して保存する。
- **「入会を認める」**(主ボタン): 年度(既定は申込日の年度)と入会日(既定は今日)を選んで押すと、人の記録(Person)と、その年度の正会員の資格(Membership、入会日つき)ができ、申込は「認めた」になって人の画面へのリンクが付く。同じ氏名の人がすでにいるときは、「この人に資格を足す」を選べる(人を二重に作らない)。操作は履歴に残り、元に戻せる。
- **「認めない」**(危険・2 回押し): 理由を必ず書く(定款第7条第2項「正当な理由」を記録する)。
- **入会のお知らせメールの下書き**: 認めたあと、申込の画面に下書きを出す(コピーして理事長のメールで送る。n-bato からは送らない)。
- **AI の転記**: AI は理事長に頼まれたときにフォームの回答を読み、`bin/rails member_applications:import` で入れる。フォームの回答の中身は Claude API にも Slack にも送らない。Slack に知らせるときは「入会申込が 1 件届きました」と件数だけ。
- 将来、n-bato に一般向けの入会ページを作るときも、入口が変わるだけで、この流れ(申込 → 認める → 会員)は変えない。

## 左のメニュー(2026-11-23 見直し第12回で合意)

区切りの見出しとページ(リンク)を、見ただけで見分けられるようにする。

- **見出し**(`nb-nav-group`): 11px・太字・`ink-muted` の色で、上に細い線(`grid-line`)を引く。押せないので、指を乗せても色は変わらない。見出しは「ふだん」「年に一度」「設定」。いつ使うページかの手がかりなので、なくさない。畳む仕組みは作らない(ページが 13 なら畳む必要がない)。
- **ページ**(`a`): 左にアイコン(14px)を付け、文字を必ず添える。アイコンが付くのはページだけ。指を乗せると地の色が付く。いまのページは `select-fill` の地・太字・左に 3px の線(年度の色を付けた画面では年度の色)。
- **ページとアイコン**:

| ページ | Lucide | ページ | Lucide |
| --- | --- | --- | --- |
| ホーム | house | やること | list-todo |
| 定款と事業 | scroll-text | | |
| 証憑・AI 仕訳 | receipt-japanese-yen | 仕訳 | book-open |
| 会計(年度) | calculator | 会員・役員 | users |
| 手続き | list-checks | 事業報告・提出 | file-text |
| 決議 | gavel | 登記 | landmark |
| 科目と部門 | tags | 法人情報 | building-2 |
| 変更の記録 | history | | |

- **「やること」の件数**(`nb-nav-count`): どの画面からも「やることがある」と気付けるように、ページ名の右に数を出す。
  - 期限を過ぎたものがあれば、その数を赤い丸(`error` の地)で出す。
  - なければ、7 日以内のものの数を黄色の丸(`dirty`)で出す。
  - どちらも 0 なら何も出さない(数が出ていないときは急ぐものがない)。
  - 指を乗せると「期限を過ぎた 11 件」のように出す。読み上げにも同じ文を付ける。
  - 済んでいないすべての数は出さない(多いままだと見慣れて見落とすため)。

## 定款と事業(2026-11-23 見直し第13回で合意)

定款・事業などの「法人のきまり」を、設定ではなく、いつでも読めるページにする(左のメニューの上の段、ホーム・やることの下の「定款と事業」。アイコンは scroll-text)。**年度に依存しない**(どの年度を操作していても同じ)。

- **タブは 3 つ**(部品 Articles): **要約**・**定款の全文**・**変更の記録**。上の欄で定款の版を選べる(既定は現行の版。前の版を見ているときは `dirty` の札で知らせる)。
  - **要約**: よく見る条をまとめる。目的・事業・会員と会費・事業年度・役員・総会・理事会・決算。条は見出し(「目的」「入会金及び会費」など)で引き、本文は条文そのものを出す(要約の文を AI が書き足さない)。条文番号を押すと全文のその条へ。
  - **事業**は表にする: 番号・事業・部門コード(仕訳の部門)・**主な活動**。
  - **定款の全文**: 左に章の目次、上に「探す」(語を含む条だけを出し、語に印)。条は `第○条` と見出し。附則は文のまま。
  - **変更の記録**: 版ごとに、決めた日と会議・議決・所轄庁(認証か届出か、その日。分からなければ「不明」と書く)・変わった条・理由・原本。前の版との違いは、条ごとに消した文(`del`、`error-fill`)と足した文(`ins`、`saved-fill`)で出す。
- **主な活動**: 事業(①〜⑨)と管理(900)ごとに、いまの活動を人が書く欄。定款ではないので年度によらず書き換え、操作履歴に残る(元に戻せる)。
  - 仕訳の部門を選ぶとき(Picker)に、部門の名前の右に灰色で出し、探す語にも入れる。AI が仕訳を提案するときの指示文にも入れる。
  - 事業報告書の画面の各事業に参照として出す。事業報告の年に一度の手続き(事業報告書を書く)で、その年度の活動と合っているかを見直す(確かめること「事業ごとの主な活動を見直した」)。
  - 推測で書かない。事業報告書などの記録にあることか、人が確かめたことだけを書く。
- **条文の参照**(部品 ArticleRef): ほかの画面の「定款第○条」「定款 第49条・第50条」は、条ごとにリンクにする。押すと右ペインのいちばん上に、**その年度の時点の版**の条文を出す(画面は移らない)。その年度の時点の版 = 年度の終わり(翌年 3 月 31 日)までに決めた版のうち、いちばん新しいもの。「閉じる」で消える。「定款の全文で見る」でページへ移る。
- 定款の本文は法人の記録として `data/`(リポジトリの外)から読み込む。リポジトリには架空の例だけを置く。

## ログイン(パスキー)(2026-11-23 見直し第14回で合意)

パスキー(端末の指紋・顔・PIN で本人を確かめる WebAuthn の仕組み)でもログインできるようにする。当面はパスワードと併用し、本番のドメインを用意したあとでパスキーだけにする(そのとき、端末をなくしたときの入り直し方を改めて決める)。

- **ログインの画面**(部品 SignIn): いちばん上に「パスキーでログイン」(主ボタン、アイコン key-round)を大きく置き、「または メールアドレスとパスワード」の区切りの下に、メールアドレスとパスワードの欄を置く。ブラウザが対応していれば、メールアドレスの欄を押したときにもパスキーの候補を出す(`autocomplete="username webauthn"`)。パスキーが使えないブラウザでは、ボタンを出さずに理由を一行で書く。
- **ログインのしかた**(部品 PasskeyList): 上部バーの名前を押すと開く。パスキーの一覧(名前・作った日・最後に使った日)、「この端末のパスキーを足す」、名前を変える(入力するとすぐ保存)、消す(2 回押し)。1 人が複数のパスキー(パソコンとスマホなど)を持てる。パスワードの欄もここに置く。
- **足す・消すは操作履歴に残す**(元に戻せない操作)。パスキーの中身(公開鍵)は画面に出さない。
- **本人の確かめ直し**: ログイン(または最後に確かめた時)から 10 分を過ぎていたら、足す・消す前に、パスワードか、いま持っているパスキーでもう一度確かめる。確かめる欄は、その場(ログインのしかたの画面の上)に出す。
- **ドメインごとに分ける**: パスキーは作ったサイトのドメインに結びつく。手元(localhost)・ステージング・本番で、それぞれ作る。親のドメインで共有しない。

## 仕訳の取消(2026-11-23 見直し第16回で合意)

記帳した仕訳は書き換えず、消さず、「取消」を記録して帳簿から外す(docs/adr/0026)。

- **どこから取り消すか**: 証憑の画面の、承認済みの提案の下の「この仕訳を取り消す」と、仕訳の表の行の「取り消す」(承認でできた仕訳の行は、書き換え・削除の代わりにこれだけを出す)。理由は必ず書く。ボタンは 2 回押し(`confirm-twice`)。元に戻せない操作として、理由と一緒に操作履歴に残す。
- **取り消したあと**: 証憑から記帳した仕訳なら、元の AI の提案と同じ内容の提案を、確認待ちでもう一度出す(AI は呼ばない)。人は正しい科目を選んで承認し直す。
- **見せ方**: 仕訳の表は、ふだんは取り消した仕訳を出さない。絞り込みの「取り消した仕訳も出す」で、薄い文字・取消線・「取消」の札(`nb-cancelled-tag`)・取り消した日と人と理由を付けて出す(行は `tr.is-cancelled`、取消線は値のセル `td.nb-struck` だけ。理由は `nb-cancelled-note`)。合計・残高・件数の合計には数えない。証憑の画面では、取り消した仕訳に「取消」の札と理由を出す。
- **取り消せないもの**: 会計王から取り込んだ仕訳(会計王で直す)。

## 待つ表示(2026-11-23 ユーザー指定)

- 裏で AI などが作業していて、結果を待つ画面(例: AI に仕訳の提案を頼んだ証憑)では、「あと何秒で読み込み直すか」を出し、0 になったら自動で読み込み直す。結果が出るまでくり返す。「少し待ってから再読み込み」のように、いつまで待てばよいか分からない書き方はしない。
- 間隔は 15 秒。「いま読み込み直す」のボタンも置く。5 分(20 回)たっても終わらなければ止めて、「時間がかかっているか、エラーが起きた可能性がある」と、次にすることを書く。
- 見た目は待ちの色(`dirty` / `dirty-fill`)の帯(`nb-flash nb-waiting`)。動きは Stimulus の `auto-reload`。

## 行き来の決まり(2026-11-23 見直し第21回で合意)

ブラウザの「戻る」を使わなくてよい画面にする(スマホでも)。docs/adr/0033。

1. どの画面からも、上の階層(パンくず)と左のメニューだけで行き来できる。
2. Nばとが返す PDF と、外のサイトへのリンクは別のタブで開き、文字の後ろに「↗」を付ける(`new_tab_link_to`)。
3. 保存や出来事の記録は、送ったあと別の画面に移る(送り直しが起きない形)。

## 表の行を直す(2026-11-23 見直し第18回で合意)

一覧の表の 1 行を、その場の入力欄で直すときの決まり。行の下に「▶ くわしく」の行を別に置くと、すぐ下の行のものに見えて取り違える(提出先の画面で起きた)。

- 行の右の端にボタンを置く。言葉は行の状態に合わせる(見直し第19回): 確かめてある行は「くわしく ▼」、手の要る行(確かめていないなど)は主のボタンの「確かめる ▼」。監査の役割では「くわしく ▼」。押すと、**その行のすぐ下**に入力欄が開き、ボタンは「閉じる ▲」になる。
- 開いた行と入力欄は、`select-fill` の地と `accent` の枠でひとつにつなぐ。
- 入力欄の一番上に「<種類>・<名前> を直しています」と、どの行かを書く。
- 一度に開けるのは 1 件だけ。ほかを開くと前のは閉じる(入力は欄の外に出たときに保存済み)。
- 足した・確かめたあとの戻り先(`#<行の id>`)の行は、はじめから開く。読み直し(morph)のあとも開いたままにする。
- 動きは Stimulus の `row-detail`。いま使っている画面: 設定 › 提出先。

## 提出先(2026-11-23 見直し第17回で合意)

書類を出す先の窓口は、法人の所在地ごとに違う。設定に「提出先」を置き、法人ごとに持つ(docs/adr/0027・0028)。

- **設定 › 提出先**(部品 FilingDestinations、アイコン send): 種類(所轄庁・法人住民税(県)・法人住民税(市)・登記・税務署・その他)ごとに、機関の名前・**書類の宛先(役職と氏名。首長が替わったら書き換える)**・窓口・住所・電話・FAX・メール・受付の時間・様式のページ・出どころ。年度には依存しない。入力するとすぐ保存し、操作履歴に残す。
- **状態の札**: 確認済み(`saved` の色)・AI の案(`dirty` の色。人が確かめる)・まだ確かめていない・直したあと、まだ確かめていない。直すと確認済みでなくなる。「この内容で確認済みにする」で確かめる。
- **書類と説明に使うのは確認済みだけ**: 提出書の「（あて先）」と、手続きの説明・やることの `{所轄庁}` は、確認済みの所轄庁から差し込む。無ければ「(所轄庁の宛先が未設定)」と書き、推測で埋めない。
- **AI に調べてもらう**: 法人の所在地と法人の種類だけを送り、Web で窓口を探して「AI の案」として足す(出どころの URL 必須)。調べている間は「待つ表示」。鍵が無ければボタンを出さない。
- **最初の起動**(部品 SetupWizard): 法人が無いときはホームから「はじめに」へ。①法人の名前と所在地 ②提出先の案(AI が調べる)③人が確かめる ④できあがり。手順の札を上に並べ、いまの手順を `select-fill` で示す。
- **様式の例**: Nばとが作る提出書類を架空の法人で 1 つの PDF にしてダウンロードできる。自治体の様式と違っていたら知らせてもらう(連絡先は設定 `NBATO_SUPPORT_URL`)。

## 提出先の一覧(2026-11-23 見直し第19回で合意)

- 列は 種類 / 機関・窓口(機関の名前、その下に小さく窓口と宛先) / 連絡先 / 状態 / ボタン。
- 連絡先: 電話番号そのものを出し、押すと電話をかける(`tel:`)。メールは「✉ メール」(`mailto:`)。無いものは `ink-muted` の小さい字で「電話なし」「メールなし」。開かなくても、入っているかが分かる。
- 下のボタンは 2 つ。「提出先を足す ▼」はメニューで、まだ行の無い種類と「その他」を出す(選ぶとその行を足して開く)。「まだ無い提出先を AI に調べてもらう(所在地だけを送る)」の下に「調べる種類: …」を出し、無ければ押せない形で「まだ無い種類はありません」。

## 住所・氏名の移り変わり(2026-11-23 見直し第20回で合意)

- 人の画面に「住所・氏名の移り変わり」の表を置く(部品 PersonHistory)。列は いつから / 住所 / 氏名 / 記録 / (取り消す)。1 行目は「記録の始まり」。
- 「住所が変わった」「氏名が変わった」のボタン(開くと `accent` の枠の入力欄)。日付は 年・月・日 で入れ、日が分からなければ空にする(推測で入れない)。表には「2025/04(日は不明)」と出す。
- 氏名が変わったときは「旧氏を併記する」を選べる。名簿・登記に「新しい氏名（旧氏 名）」と書く。
- 打ち間違いは、いちばん新しい出来事の「取り消す」(理由は必須・2 回押す)で取り消して入れ直す。取り消した行は取消線と「取消」の札。
- 代表権のある理事の住所・氏名が変わると、その行に「登記がいる(期限 …)」と出す。
- 出来事のある人は、編集の画面で氏名・住所を直せない(出来事で足す)。

## 登記の申請(2026-11-23 見直し第20回で合意)

- 登記の画面の上に、登記・供託オンライン申請システムへの主のボタン(別のタブ)と、いま使えるか(`saved` / `dirty` の色の札。例「いまは使えます。今日は 23:00 まで」)、使える時間・法務局の受付の時間・いま送ったら何日の受付か・運転状況へのリンクを出す(部品 RegistrationOnline)。
- 「登記がいること」の表(登記すること・人・原因の日・期限・申請)。期限を過ぎた行は `dirty` の字。選んで「選んだもので登記の申請を始める」。
- 登記の申請 1 件の画面(部品 RegistrationFiling): 手順の札「何を登記するか → 書類を作る → 申請した → 受付 → 補正(あれば) → 完了」(済みは `saved`、いまは `select-fill` と `accent`、補正が無ければ点線で「(なし)」)。
- 「登記すべき事項」は等幅の文で出し、「登記すべき事項の文をコピー」(主のボタン)。確かめること(日が不明など)は警告の帯。添付書類は PDF のリンク(内訳・互選書・定款・議事録)。
- 申請したあとの記録(申請した・受付・補正・完了・取り下げ)は、その段階で使うものだけをフォームで出す。完了と取り下げは 2 回押す。

## 右ペイン(2026-11-20 追加。確認は最後の確認ページで)

右ペインには上から、**この画面の使い方**(HelpPanel)、**AI に聞く**(AskAI)、**操作履歴**(HistoryPanel)を置く。

- **説明は一目で説明と分かる見た目にする。** `guide-fill` の地、左に `guide-line` の線、info のアイコン、見出し「この画面の使い方」。説明以外にこの見た目を使わない(`guide-fill` は説明だけに使う)。
- **役割に合わせる。** 事務の人には、すべての操作の説明。監査の人(監事)には、この画面に出ているものと、ほかに出せるもの(監査の役割は閲覧だけ)。
- **いまの状態を先に。** 仮の年度・締めた年度・絞り込み中など、いまの状態に関わる説明を上に出し、そのあと「操作 → どうなるか」の短い一覧。段落の文は書かない。キーは `kbd`。
- **畳める。** 見出しの「畳む」で畳む。畳んでも見出しは残り、「開く」でいつでも戻せる。畳んだかどうかは人ごと・画面ごとに覚える。
- **AI に聞く。** やりたいことを書くと AI が答え、できる操作なら「やる操作の案」を出す。操作は人が「実行」を押してから行い、操作履歴に残る(元に戻せる)。画像を添えて「仕訳して」で証憑として登録し、AI 仕訳の提案を作る。欄の下に「ここに書いた文と画像は Claude API に送ります」と書く。個人情報を含む頼みごと(会員の住所を直すなど)には使わない(2026-11-21 決定)。人の記録は人の画面で直し、AI はその手順を答えるだけにする。欄の下にもそのことを書く。

## 部品の説明

### AppShell

1 画面の骨組み。上部バー・左メニュー・シート・右ペイン・下のタブ。README の「画面の骨組み」の実物。

- 画面全体の高さに収め、スクロールはシートと右ペインの中だけ。
- 上部バー: 画面名、年度、空き、保存状態、元に戻す・やり直す、履歴の開閉。
- 右ペインは畳める(畳むと `grid-template-columns` の 3 列目を 0 に)。

### Brand(製品名)

製品名は **n-bato**(NPO butler の略「Nばと」)。

- **日本語では「N(エヌ)ばと」と書く。** 画面では N に「エヌ」のルビを振る: `<span class="nb-brand"><ruby>N<rt>エヌ</rt></ruby>ばと</span>`。
- ルビが使えない所(ページのタイトル、メール、Markdown、帳票の欄外)では「N(エヌ)ばと」と括弧で書く。2 回目からは「Nばと」でよい。
- 英字では **n-bato**(n の後ろにハイフン)。リポジトリ名・URL・コードの中はこちら。nbato とは書かない。
- 上部バーの左端に `brand`(15px 太字・`accent`)で置き、ルビは `brand-ruby`(10px・`ink-muted`)。ルビは読みを補うためだけの例外で、ほかの文字は 11px より小さくしない。
- 所轄庁に出す書類には製品名を入れない。

### Button

ボタン。普通・主(`--primary`、1 画面に 1 つ)・危険(`--danger`)。文字は動詞で終える。

- 元に戻せない操作(承認して記帳、提出日の記録、決議の反映、登記の記録)は `--danger`。1 回目で `--armed` になり「もう一度押すと実行」と表示、2 回目で実行する。横に `nb-btn-note` で「取り消せません」。ダイアログは出さない。
- 保存ボタンは作らない(入力したら保存される)。

### Checklist(確かめること)

手順の中の、用意するもの・確認すること・同意の返事の一覧。1 行は `row-height`。

- チェックした時点で保存し、履歴に「確認: 〜」と残す。外すのも元に戻すのも同じ。
- 右の `meta` に、数字(残高など)・日付・返信の有無を出す。
- 相手の返事を待つ行は `is-waiting`(`step-waiting-fill` の地)と「待ち · いつ送ったか」。
- 済んだ行は文字を `ink-muted` にする(取り消し線は引かない。読めなくなるため)。
- 人の名前は、役員・正会員の記録から出す。名簿にない人を手で足さない。

### Deadline(手続きの見出し)

Procedure の上に置く 1 行。ホームの「やること・期限」の 1 行にも同じ部品を使う。

- 左から: 手続き名、対象の年度(StatusTag の plain)、期限と残りの日数、進み具合、次にやること。
- 残りの日数は `countdown`(15px 太字・等幅の数字)。
  - 30 日より先: `ink`「あと 222 日」
  - 30 日以内: `nb-due--soon`(`step-waiting`)「あと 14 日」
  - 過ぎた: `nb-due--overdue`(`step-overdue`)「143 日超過」
- 進み具合の棒は、済み(`step-done`)と待ち(`step-waiting`)を分けて塗り、横に「3 / 9 済み」と文字でも書く。対象外は済みに数える。
- 次にやることは、済み・対象外・待ちを除いた最初の手順。

### Field

詰めた入力欄。見出しが左、値が右の 2 列で、1 行 `row-height`。詳細ペインや設定の画面に使う。

- 入力欄(`nb-input`)は枠を見せず、触れると枠、入力中は選択枠と同じ 2px。
- 状態は Sheet と同じ: `--dirty`、`--error`、`readonly`。
- 離れた時点で保存する(保存ボタンは置かない)。

### HistoryPanel

操作履歴。右ペインに新しい順で出す。選んだ行の履歴だけに絞ることもできる。

- 1 件に、時刻、何をしたか、変更前 → 変更後、した人を出す。
- 元に戻した操作は `li.is-undo`(`history-mark` の ↶ 印)。
- 削除した行は、履歴の項目から「復元」できる(復元も 1 件の操作として残る)。
- 日付が変わるところに日付の見出しを入れる。

### Procedure(手順の画面)

年に一度(役員改選は 2 年に一度)しかしない手続きを、**前回どうしたかを忘れていても進められる**ようにする画面。事業報告書等の提出・通常総会・役員改選・役員変更の届出・登記・決算に使う。

## 骨組み

AppShell の中のシートの場所に置く。

- **見出し**(Deadline): 手続き名、対象の年度、期限と残りの日数(過ぎていれば超過した日数)、進み具合、次にやること。
- **手順の一覧**(Stepper、左 `step-list-width`): すべての手順を縦に並べ、状態を印で示す。
- **手順の中身**(StepPanel): なにを・なぜ(根拠の条文)→ 確かめること(Checklist)→ この手順で作る書類 → 済みにする。
- **右ペイン**: 前回(去年・2 年前)の同じ手順の日付とメモ、操作履歴。

## 決まり

- **手順は順に並べるが、順番を強いない。** どの手順でも開いて見られ、先の手順の書類も作れる。前の手順が済んでいないと困るときだけ、「済みにする」の横に理由を書いて押せなくする(待ち・未確認)。
- **途中でやめても、そのまま続きから。** チェック・記録はすぐ保存する。何週間かかっても(同意書の回収など)、開けば止まったところが出る。
- **なぜやるのかを必ず書く。** 説明(guide)には根拠の条文(定款・NPO 法)と期限の決まりを添える。1 年たつと理由を忘れるため。
- **前回を見せる。** 右ペインに前回の日付・やり方・メモを出す。初めての年は「前回の記録はありません」と書く。
- **状態は 6 つ**: 未着手・進行中・待ち・済み・期限切れ・対象外。色・印の記号・文字の 3 つで示す。
- **待ちは相手を書く。** 誰の何を待っているか、いつ送ったかを Checklist の行に出す(`is-waiting`)。
- **済みにするのは元に戻せる。** ただし所轄庁への提出日・登記の申請日など、外に出たことの記録は Button の「危険」(2 回押し、取り消せません)にする。
- **次にやること** はホームの「やること・期限」にも同じ文で出す。

### SaveStatus

上部バーに置く保存の状態。保存ボタンの代わりに、いま保存されているかを知らせる。

- 状態は 5 つ: 普通(`nb-save`)、入力中(`--dirty`)、保存中(`--saving`)、保存しました(`--saved`、時:分を付ける)、保存できませんでした(`--error`、理由と再試行)。
- 色と、点(丸)・四角の形の両方で示す。エラーのときは太字。
- 文言は短く:「入力中」「保存中…」「保存しました 10:42」「保存できませんでした(通信が切れました)」。
- 上部バーだけでは目に入らないので、**保存したセルも 2 秒だけ `saved-fill` にする**(`is-saved`)。目はセルを見ているため。

### Sheet

Excel のような表。仕訳・会員・証憑など、記録を一覧して直接直す画面の中心に置く。

- 列見出しは固定(`position: sticky`)、合計行も固定。シートの中だけがスクロールする。
- 1 行は `row-height`。金額の列は `nb-num`(等幅・右寄せ)、マイナスは `nb-neg` と「−」。
- セルの状態はクラスで付ける: `is-selected`(選択枠)、`is-editing`(入力中。中に `input`)、`is-dirty`(未保存)、`is-saving`、`is-saved`(1 秒で外す)、`is-error`、`is-readonly`。状態は地の色と右上の三角の両方で示す。
- 選択中の行は `tr.is-selected-row`。右ペインにその行の詳細と履歴を出す。
- 動き(キー操作・保存・元に戻す)はアプリ側で付ける。キーの割り当ては README の「キーボード」。
- アプリ側が用意するもの: 各セルの `data-record` と `data-field`(保存先)、変更できない理由。
- **行番号は出さない。** 並びで変わる番号は人に伝えられない。記録を指す番号(伝票番号など)だけを出す。
- **変更できない行(`is-readonly`)を押したら、理由と直し方を出す**(例:「会計王の仕訳です。会計王で直して取り込み直してください」)。何も起きないと壊れて見える。
- **並びが変わる変更**(日付順の表で日付を直すなど)は、すぐ正しい位置へ移し、移った行を 2 秒 `select-fill` にして、行が見えるところまでスクロールする。
- **新しい行**: 表のいちばん下に空の行(`tr.is-new`)を置き、そこに書き始める。必須の項目(仕訳なら日付・科目・金額)がそろうまでは `is-dirty` のまま保存せず、そろった時点で 1 件の記録として保存する(1 つの操作)。保存したら下にまた空の行を出す。別の画面に移る「＋ 追加」ボタンは置かない。
  - 日付の初期値: 今日が操作している年度の中なら空にする。年度の外(過去の年度・締めた年度)なら、直前にその年度へ足した記録の日付、無ければその年度のいちばん後の記録の日付を入れておく(カレンダーが今日の月で開くと、年度の外の日付を入れやすいため)。
- 一覧から選ぶ値(科目・部門など)は `Picker` を使う。長いドロップダウンは使わない。
- 絞り込みは表の上の `FilterBar`、集計は表の下の `SheetFooter`。列見出しは押しても何もしない(並び順は表ごとに決める)。

### SheetTabs

切り替えのタブ。Excel のシート見出しのように、シートの下に並べる。

- **年度の切り替えには使わない**(下は気づかれにくい。2026-11-20 の見直しで決定)。年度の扱いは見直し票の第2回で決めてから「年度」の節に書く。

- 選んでいるタブは `aria-selected="true"`(太字と accent の下線)。
- 切り替えても画面の他の部分(選択、右ペイン)は保つ。

### StatusTag

状態の札。期限の一覧、提出の状況、証憑の処理状況に使う。

- `--overdue` 期限切れ、`--soon` 期限が近い・確認待ち、`--done` 完了、`--plain` そのほか。
- 枠と地の両方で区別し、文字で状態を書く(色だけにしない)。

### StepPanel(手順の中身)

開いている手順の中身。上から順に、いつも同じ並びにする。

1. **見出し**: 番号・手順名・状態の札(StatusTag)。
2. **説明**(`nb-guide`): なにをするか、どうなれば済みか を 2〜3 文で。下の `dl` に **根拠**(定款・NPO 法の条文)、期限の決まり、必要なら議事録に書くこと。文字は `guide`(14px・行間 24px)で、`guide-measure` より広げない。
3. **確かめること**(Checklist): 用意するもの・確認すること・同意の返事。
4. **この手順で作る書類**: 書類を開くボタン(帳票は明朝・黒一色の別の画面)。
5. **済みにする**(`nb-stepfoot`): 主ボタン。押せないときは、横に理由と、あといくつかを書く。外に出したことの記録(提出・申請)は、危険のボタン(2 回押し)と「取り消せません」。

- 説明の文は、事務員の言葉で、1 年後に読んでも分かるように書く。「〜します」で終える。
- 条文は番号だけでなく、何の条文か(「書面による同意」など)を添える。

### Stepper(手順の一覧)

手続きのすべての手順を縦に並べる。Procedure の左の列(`step-list-width`)。

| 状態 | クラス | 印 | 下の行 |
| --- | --- | --- | --- |
| 未着手 | (なし) | 番号・枠だけの丸(`step-todo`) | 「未着手」 |
| 進行中 | `is-current` | 番号・塗りの丸(`step-current`) | 確かめた数「1/2 確認」 |
| 待ち | `is-waiting` | 「…」(`step-waiting`) | 待っているもの「同意書 3/4」 |
| 済み | `is-done` | 「✓」(`step-done`)。下のつなぎ線も緑 | 済んだ日 |
| 期限切れ | `is-overdue` | 「!」(`step-overdue`) | 期限の日付(太字) |
| 対象外 | `is-skipped` | 「－」・点線の丸(`step-skipped`) | 理由「収益事業なし」 |

- 開いている手順は `aria-current="step"`(地は `select-fill`、左に `accent` の線)。状態とは別。
- 状態は色・記号・文字の 3 つで示す。読み上げ用に、題の後ろへ「(済み)」などを隠して入れる。
- 当てはまる年だけの手順は、最後に「当てはまれば」(`nb-step-group`)の下にまとめる。
- ↑ / ↓ で手順を移る。Enter で中身に入る。

### UndoBar

元に戻す・やり直すのボタン。記録を直せる画面では必ず上部バーの右に置く。

- ボタンに件数(`kbd`)を出す。0 件なら `disabled`。
- **ボタンに、戻る(やり直す)操作の項目を出す**(「元に戻す: 金額」)。指を乗せると、変更前と変更後の値を出す(「金額 1,280 → 1,000」)。
- **元に戻したら、戻した記録のある画面・年度・行へ移り、そのセルを 2 秒光らせる**(`is-saved` と同じ扱い)。見えない場所で戻ると、何が起きたか分からないため。
- ⌘Z / Ctrl+Z、⌘⇧Z / Ctrl+Y と同じ動き。
- 元に戻すは「逆の操作を新しく記録する」ので、履歴は消えない。元に戻せるのはその画面で自分がした操作だけ。
- 承認・提出日の記録・決議の反映など、元に戻せない操作は対象にしない(Button の「危険」を使う)。

### Picker(一覧から選んで入れるセル)

科目・部門など、決まった一覧から選ぶセル。ドロップダウンの代わり。

- 打った文字で絞り込む。コード(「100」)、名前の一部(「消耗」)、読み(「げんきん」)のどれでも当たる。
- 候補はセルの下に `shadow-pop` で 8 行分の高さに出し、それより多いときはスクロールする。開いたときは、いまの値の行を選んだ状態にする。
- **最初は、これまでの仕訳で使ったものだけを出す**(2026-11-21 見直し第8回)。一覧のいちばん下に「すべての科目を出す(ほか N 件)」(`li.nb-picker-more`)を置き、選ぶと残りも含めた一覧を別に取りに行って出し直す。全件を最初から画面に入れない(件数が増えても重くならないように)。件数で切って先の候補を選べなくすることはしない。打った文字に使ったものが当たらないときは「当てはまるものがありません」の下に「すべての科目から探す」を出す。↑↓ で選び、Enter で決めて保存、Esc で元の値に戻す。
- 1 件にしぼれたら Enter だけで決まる。どれにも当たらないときは「当てはまる科目がありません」と出し、保存しない。
- 候補の行は「コード 名前」の形で、コードは `nb-num`。

### FilterBar(絞り込み)

表の上(ツールバーの下)に置く絞り込みの欄。仕訳なら科目・部門・摘要。

- 科目・部門は `Picker` と同じ選び方、摘要は文字の一部。
- 絞り込んでいる間は、欄の左に「絞り込み中: 現金」の `StatusTag --soon` と「解除」を出す。件数は `SheetFooter` に「3 / 10」の形で出る。
- 絞り込みは画面を離れても保つ(同じ人・同じ画面)。

### SheetFooter(表の下の集計)

表の下に固定する集計の行。Excel の画面下の集計に当たる。

- 既定は件数(選んだ件数 / 全件、絞り込み中は絞り込んだ件数)と、選んだ行の金額の合計。行を Shift・⌘ で複数選ぶと合計が変わる。何も選んでいなければ件数だけ。
- 全行の金額を足しただけの数は出さない(何の残高でもないため)。
- 出せる集計(第2回で合意): 件数、選んだ行の合計、絞り込んだ科目の残高(期首の残高 + 借方 − 貸方。科目で絞り込んだときだけ)、平均・最大・最小。
- 表の下の「▾ 出すものを選ぶ」を押して選ぶ(Excel の右クリックの代わり)。選んだものは人ごと・画面ごとに覚える。
